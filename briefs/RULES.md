# 每日財經早報（給客戶看）— 雲端排程規則

> 這份是雲端排程每天 09:00（台灣時間）要照做的完整規則。要改早報的做法，就改這份。
> 讀者是 Edward 的客戶和潛在客戶，包括上班族、小資族和高資產家庭。這份早報會**公開**在網站上。
>
> **Blog 早報只放四種內容**（Edward 2026-11-17 指定）：
> ① 新聞資訊　② 交叉比對（**只列出處**，Edward 2026-11-18 指定）　③ 簡單分析（為什麼重要）　④ 推估可能（標明是推估，列出條件與情境）
> 這份和 Edward 自己看的「個人早報」是兩件事：個人早報在私人 repo，照原本做法不動；這份不碰任何個人早報的內容。

## 絕對不可以
1. 不寫任何客戶資訊，包括姓名、保單、金額、對話內容，以及任何能認出是誰的線索。
2. 不寫 Edward 的工作內容、行程、業績、公司內部資料，也不推銷任何商品。
3. 新聞、交叉比對、分析都只寫**事實與時事**。「推估可能」一定要標明是推估，要寫「如果…，可能…」，並附上依據。不給買賣建議（不能寫「建議買進／賣出」「可以布局」「目標價」），也不寫成「一定會」。
4. 不照抄新聞原文：一律用自己的話重寫。真的需要引用，一則最多引用一句，而且不超過 15 個字。
5. 不使用新聞網站的照片。圖片由網站自動產生，你只要提供數字和分類。
6. 只改 `briefs/` 底下的檔案，其他檔案一律不碰。

## 步驟

### 0. 準備
- 執行 `git pull --ff-only origin main`。
- 今天日期以**台灣時間**為準：`TZ=Asia/Taipei date +%F`，以下稱 DATE。
- 如果 `briefs/data/DATE.json` 已經存在，代表今天跑過了，直接結束。

### 1. 讀 Edward 的方向建議
執行：
`curl -s "https://firestore.googleapis.com/v1/projects/edward-blog-a6317/databases/(default)/documents/settings/brief"`

取出 `fields.direction.stringValue`。有內容就照著調整選題方向；讀不到就當作沒有建議。

### 2. 讀收盤數字
雲端排程的網路連不到 Yahoo，所以收盤數字由 GitHub Actions 先抓好（台灣 07:37、08:17、08:47、09:23、10:53 各排一次；早報推上來後也會自動重抓一次，並把最新收盤補進今天的早報，所以就算這裡讀到舊數字也會被修正），存在 `briefs/market/latest.json`。這一步只要讀這個檔，**不要自己再去抓**。
- 把 `items` 放進 `market`，每一筆加上 `asOf`，格式是「台股 MM/DD、美股 MM/DD」，日期取各自的 `date`。
- 如果 `updatedAt` 不是今天：照樣使用，但在 `asOf` 註明「（資料時間 updatedAt）」。
- 如果檔案不存在：`market` 給空陣列，網站會略過行情區。

### 3. 找新聞，寫 6～10 則候選
用 WebSearch 找**過去 24 小時**的重要財經時事，總共寫 6～10 則候選。優先順序：
1. 台股、美股大盤的大波動和原因
2. 央行和利率（聯準會、台灣央行）
3. 匯率
4. 重要經濟數據（CPI、就業、GDP）
5. 和台灣關係大的產業，例如半導體
6. 政策和法規，例如稅、勞保健保、退休制度
7. 國際大事

**固定要找的四個主題（Edward 2026-11-18 新增）**：每天各找 1 則，有通過查證就寫，沒有就跳過，不要硬湊。
- **貴金屬**：黃金、白銀價格與原因（央行買金、美元、利率）。
- **科技產業**：台積電、蘋果、半導體供應鏈等大公司的營運與產業動向（不是 AI 也可以）。
- **AI 產業**：AI 公司的財報、投資、併購、晶片與資料中心。
- **AI 新功能**：ChatGPT、Claude、Gemini 等一般人用得到的新功能或新產品；`why` 要寫「一般人可以怎麼用」。

**零容忍查證**（違反一條就刪掉那一則）：
- 從搜尋結果的「標題」或「網址」確認發布日期在 24 小時內。不能只看 WebSearch 自動產生的摘要，摘要常常會把日期弄錯。
- 每個數字至少要有 **2 個不同網站**互相印證，才可以寫進去。
- 查不到日期、兩個來源的數字對不上，就不寫這一則。寧可少寫，也不要寫錯。

**每一則的寫法**（白話，國中生也看得懂）：
- **台美股大盤表格（Edward 2026-11-19 指定一定要有）**：網站會把 `market`（latest.json 的台股加權、S&P 500、那斯達克、道瓊、費城半導體、美元/台幣）每天固定畫成「現價／開盤／漲跌／收盤」表格放在最上面，所以 `market` 一定要放齊；新聞內文不用再重複這些數字。
- **大盤數字（Edward 2026-11-18 更新）**：只要內容和大盤有關（台股加權、S&P 500、那斯達克、道瓊、費城半導體），一定要加 `index` 欄位，把 `briefs/market/latest.json` 裡那幾筆**整筆**放進陣列，例如 `"index": [ {latest.json 的台股那一筆} ]`。網站會自動畫成「現價／開盤／漲跌／收盤」小表格。
  - 因為已經畫成表格，`facts` **不要再寫**「台股 2026.11.17，開盤下跌…收在…點」這種開盤收盤句，直接寫原因、背景等其他事實。
- `title`：15～28 字，講清楚發生什麼。
- `facts`：2～3 句，只寫事實，要有數字或日期。
- `crossCheck`：**一律填空字串 `""`**。交叉比對在網站上**只顯示出處**（自動用 `sources` 的網站名稱＋日期），不寫說明文字（Edward 2026-11-18 指定）。查證還是要照上面的零容忍規則做，只是不寫出來。
- `why`：**簡單分析**，用第一性原理說明為什麼重要，2～3 句。從最基本的因果推起：錢從哪裡流到哪裡、誰的成本或收入會變、這件事會怎麼影響一般人的房貸、薪水、物價、存款或投資。不寫空話。
- `outlook`：**推估可能**，給 1～2 個情境。格式是「如果（條件），可能（結果），因為（依據）」，例如「如果下週 CPI 仍高於 3%，聯準會 12 月升息的機率可能提高，因為市場目前的定價已經反映……」。依據要來自新聞或數據，不能憑空猜。不確定的話寫成「仍待觀察：要看（指標）」。
- `category`：從這些選一個：台股、美股、總經、利率、匯率、產業、政策、國際、原物料、加密貨幣、貴金屬、科技產業、AI產業、AI新功能（不要加空格）。
- `number`：這則最關鍵的一個數字，例如 `{"value":"-2.49%","label":"那斯達克單日"}`。沒有就填 `null`。
- `sources`：至少 2 個**不同網站**（轉載同一篇稿的只算 1 個），這就是網站上的「交叉比對（出處）」，格式 `{"name":"網站名","url":"…","date":"MM/DD"}`。
- `pros`：放這則的好處，一句話。例如「跟讀者的房貸直接相關」。
- `cons`：放這則的壞處，一句話。例如「太專業」「跟昨天重複」「還在發展中，數字可能改」「有政治爭議」。
- `score`：重要度 1～5。
- `recommend`：最值得放的 3～4 則填 `true`，其他填 `false`。

### 4. 今日一句話和財經小知識
- `headline`：一句話講今天最重要的事，不超過 40 字。
- `knowledge`：挑一個跟今天新聞有關的財經名詞，格式 `{"term":"…","explain":"白話 2～3 句","example":"生活化的例子"}`。
  - 先看 `briefs/index.json` 最近 30 天用過哪些名詞，不要重複。

### 5. 寫檔
`briefs/data/DATE.json` 的格式如下，`id` 用 c1、c2…：
```json
{
  "date": "DATE",
  "generatedAt": "ISO 時間",
  "headline": "...",
  "market": [ ... ],
  "candidates": [ { "id": "c1", "title": "...", "facts": "...", "index": [ ... ], "crossCheck": "", "why": "...", "outlook": "...", "category": "...", "number": {...}, "sources": [...], "pros": "...", "cons": "...", "score": 4, "recommend": true } ],
  "picks": ["c1", "c3", "c4"],
  "knowledge": { "term": "...", "explain": "...", "example": "..." }
}
```
- `picks` 就是 `recommend` 為 `true` 的那幾則的 id。
- `briefs/index.json` 的格式是 `{"dates":[...]}`：把 DATE 加進去，排好序。
- 用最近 30 天的 `knowledge.term` 維護 `"terms"` 清單。

### 6. 只保留一年
- 刪除 `briefs/data/` 裡日期早於「今天往前 365 天」的檔案，`index.json` 也要一起移除這些日期。

### 7. 驗證、上傳
- 執行 `python3 -c "import json;json.load(open('briefs/data/DATE.json'));json.load(open('briefs/index.json'))"`，確認 JSON 格式正確。
- 只 `git add` 這次動到的 `briefs/` 檔案，不能用 `git add -A`。
- commit 訊息：`早報 DATE`。
- 執行 `git push`。如果被拒，先 `git pull --rebase` 再推一次。

### 遇到問題
- 找不到任何通過查證的新聞：仍然寫檔，`candidates` 給空陣列，`headline` 寫「今日市場數字整理」。網站會只顯示行情和小知識。
- 不要用任何連接器，例如 Gmail、Notion。這份工作只需要網路搜尋和這個 repo。
